1. Project Objective 
The goal of this project is to design and implement an autonomous software system that 
allows a TurtleBot3 Burger to complete a mission. You must integrate kinematics, sensor 
perception, obstacle avoidance, localization, and path planning to solve real-world navigation 
challenges in a dynamic environment. 
 
2. The Mission 
The mission is divided into three sequential phases. The robot must evolve without external 
assistance throughout all stages. 
 
Phase I: Global Navigation & Obstacle Avoidance 
Starting at Punt A (4.280, 1.735), the robot has to navigate through waypoints C, D, and F, 
reaching the Door (6.280, 11.685). 
The environment may contain static or dynamic obstacles not present in the initial map. You 
have to implement a real-time obstacle detection and avoidance procedure. 
 
Phase II: Perception & Area Exploration 
Once the robot reaches the Door, it has to explore the "Passadis" (corridor) area by visiting 
waypoints Q (9.115, 14.190), R (7.310, 16.190), S (3.675, 14.190), T (1.275, 14.990), and 
U (1.075, 16.190), while locating the charging station. The station is a 40 cm x 40 cm square 
structure supported by four pillars (approx 5 cm diameter). 
Once completely explored and the station is identified, the robot has to return to P Base 
(3.475, 15.390). The "passadis" area measures no more than 12 by 12 meters. 
While completing Phase I and Phase II the robot has to build his own environment map. 
You must submit the map file (.yaml  and .pgm) generated by the robot during the mission. 
This map must be the result of the robot’s own sensors and SLAM implementation processed 
during the completion of the first two phases, demonstrating the robot's ability to reconstruct 
the environment accurately (walls, other fixed objects no t included in the prior map, 
obstacles, …, and the charging station pillars). 
 
  Phase III: Precision Docking 
Finally, from P Base (3.475, 15.390), the robot has to execute a high-precision maneuver to park the 
robot exactly in the middle of the charging station. This action completes the robot mission. 
 
The navigation system must prioritize the physical integrity of the TurtleBot3 platform. Path 
planning must be intrinsically safe, incorporating a conservative clearance buffer from all 
obstacles. In alignment with professional robotics standards, any phys ical collision with the 
environment will result in a severe grade penalty.

4. Evaluation Criteria 
The project will be presented in a live demo at the lab, using the real TB3 robot. 
Your project will be graded based on the following metrics: 
• Engineering Standards: Code quality (PEP8), project methodology, and technical 
documentation. 
• Navigation Quality: Safety of the path, total distance traveled, and time efficiency. 
• Localization Accuracy: Precision of the final pose , waypoints and in the charging 
station. 
• Perception & Avoidance: Effectiveness of the sensor analysis in detecting pillars and 
avoiding unknown obstacles. 
Remember: Zero-tolerance for collisions. Any impact between the robot and its 
surroundings—static or dynamic—will be heavily penalized during the final assessment.
